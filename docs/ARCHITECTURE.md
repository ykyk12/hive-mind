# 架构与设计决策

本文记录"为什么这么做"，以及**不这么做会出什么问题**。所有结论都对应代码位置，可逐条核对。

## 1. 分层与依赖方向

```
change（变更模型/仓库/审计）←── govern（提议·审核·门锁）
        ↑                              │
        └──── evolve（编译·冒烟·制品·回滚）
agent（循环·工具·风险门） ── 端口 ──► skill（技能库·经验总线） ──► cluster（选举·心跳·反熵·下发）
```

- `agent` 只定义端口（`SkillAdvisor`、`ExperienceRecorder`），实现在 `skill` —— 这样 Agent 循环不依赖记忆实现，也没有包循环。
- `change` 只放数据与仓库，`govern` 与 `evolve` 都依赖它，彼此不互相依赖（`govern → evolve` 单向）。

## 2. 角色弹性：同构节点 + 租约选举

**代码**：`cluster/ElectionService`、`cluster/NodeRegistry`、`cluster/HeartbeatService`

- 启动一律 `NEURON`；`term` 单调递增；竞选需要 `clusterSize/2 + 1` 票（`quorum()`）。
- 大脑持有**租约**：只有拿到多数派心跳确认才续租（`recordLeaseAcks`），否则租约到期自动卸任 → 避免"一个失联的大脑继续发号施令"。
- 随机选举超时（租约 + [0, 租约) 抖动）避免多节点同时竞选造成活锁。
- 投票规则：term 更大者优先；同 term 下若本节点已有有效大脑则拒绝；权重更高者优先。

**不这么做会怎样**：没有 term/quorum，一次网络抖动就会出现两个大脑，同一批神经元接到两套互相冲突的指令；没有租约，一个被网络隔离的大脑会继续接受并应用"全局变更"，而它其实已经不代表多数派。

## 3. 多模型路由：画像 + 在线学习 + 断熔

**代码**：`model/ModelRouter`、`model/ModelStats`、`model/CircuitBreaker`

排序分 = 能力匹配（+40）+ 成功率 EMA（×30）+ 人工权重（≤30）− 成本（每 1k 输入价 ×1000）− 延迟（≤10）。

- 成功率先验取 **1.0（乐观）**：新接入的模型不该因为"还没跑过"就被成本项压到底部。
- 失败按降级链顺序换下一家；连续 3 次失败 → 断熔 30 秒，避免每次调用都白等一次超时预算。
- `fanout` 提供"同一问题问多家"的并列展示：**多数投票只在答案可判定对错时有意义**（代码能跑测试、事实可核对），开放式问答投不出正确答案，所以这里只展示不合并。

## 4. 经验：制品化 + 适应度 + 跨节点验证

**代码**：`skill/SkillArtifact`、`skill/SkillStore`、`skill/ExperienceBus`、`cluster/GossipService`

- 技能是**不可变制品**（含版本、来源节点、触发条件），改动一律产生新版本 → 可回滚、可追溯。
- 适应度是成功率 EMA（先验 0.5 中性），使用上报来自本节点与远端节点。
- 召回 = `max(词级重合, 字符二元组重合) × 2 + 适应度`；相关度为 0 一律不注入（把不相关"经验"塞进上下文比没有经验更糟）。
- **只有**满足"验证节点数 ≥ 2 且适应度 ≥ 0.6 且使用次数 ≥ 3"的技能才会通过 `promotableArtifacts()` 进入 gossip 广播。
- 失败轨迹只计入统计，**不蒸馏**——把失败结论固化成"经验"比不学更危险。

## 5. 自改：三权分立 + 确定性门锁 + 制品指针

**代码**：`govern/Proposer`、`govern/Reviewer`、`govern/Governor`、`evolve/EvolutionPipeline`

```
提议者(模型) ──提案──► 审核者(规则) ──结论──► 门锁(确定性) ──放行/升级人工──► 隔离编译 → 冒烟 → 制品归档 → 指针切换
```

- 审核与门锁**都不调用模型**：提交给模型"你觉得这个改动安全吗"等于把刹车交给被告。
- 自审禁令：审核者 ≠ 提议者；签名人 ≠ 提议者且 ≠ 审核者（`GovernanceService` 抛 409）。
- 门锁三条线：**否决**（缺审核/审核否决/自审/无收益声明/成本涨而成功率不涨）、**升级人工**（非自动放行类型、内核变更、风险分超阈值）、**定向**（方向规则）。
- 编译用 `javax.tools`，类加载用**子优先**隔离加载器（父加载器只提供接口，保证 `instanceof Tool` 成立）；
- 候选代码先落 `hive/workspace/{proposalId}`，通过后才归档到 `hive/artifacts/{name}/v{n}` 并切换注册表指针 → 失败就地丢弃，不影响正在服务的实例。

**已知代价**：类加载器用完即关，热加载会产生新的类实例；真正的高频热替换需要处理 Metaspace 与 ClassLoader 泄漏，本项目把切换粒度限定在"注册表指针 + 制品版本"。

## 6. 三种真实失败模式与对策

| 失败模式 | 为什么会发生 | 本仓对策 |
|---|---|---|
| **崩溃传染** | 同构节点 + 共享经验 ⇒ 一个坏制品/坏经验全网同时生效 | 技能跨节点验证才广播；制品按节点灰度（M4 计划）；演进失败就地丢弃 |
| **行为同质化** | 所有节点都吃同一批经验 ⇒ 探索能力退化，只养了一个 Agent | 技能只在触发条件匹配时注入；预留 A/B 影子对比（M2）；允许节点保留本地未推广经验 |
| **记忆污染** | 把一次偶然成功的错误结论当成通用经验 | 只蒸馏"成功且多步"的轨迹；失败轨迹不蒸馏；适应度可下降并触发淘汰 |

## 7. 边界与取舍

- 不引数据库：demo 零依赖优先，接口已隔离，后续可换 Redis/PostgreSQL。
- 不引 LLM SDK：OpenAI 兼容协议 + JDK HttpClient 已足够，依赖面越小越不容易被版本冲突拖死。
- 不做内核热替换：风险与收益不匹配，且"能改内核"不构成任何 demo 优势。
- 状态在内存：重启清空是明确取舍，不是遗漏（见 README 已知边界表）。
